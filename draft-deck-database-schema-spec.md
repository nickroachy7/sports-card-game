# Draft Deck — Database Schema Specification (v0.1)

**Companion to:** `draft-deck-gameplay-spec.md` (v0.2), `draft-deck-tech-stack-spec.md` (v0.1), `draft-deck-balldontlie-integration.md` (v0.1).
**Status:** Canonical schema. Supersedes the table sketches in gameplay §20, tech §4, and BDL §10.
**Database:** Postgres (via Supabase) — Postgres 15+.
**Access:** Drizzle ORM for type-safe queries; raw SQL migrations applied via Supabase CLI; Supabase Realtime subscriptions on select tables.
**Scope:** Every table, every column, every relationship, every index, every RLS policy, every enum needed for the Draft Deck launch.

---

## 1. Design Principles

1. **Schema-as-code.** Tables are defined in Drizzle TypeScript under `src/lib/db/schema/*`. Migrations are generated by `drizzle-kit` and applied via Supabase CLI. Diffs are reviewed before merge.
2. **RLS by default, always.** Every table has RLS enabled. No "row-level security off" tables in production.
3. **Normalized with a few pragmatic JSONB escape hatches.** Structured queries live on relational columns. JSONB is reserved for truly opaque payloads (raw webhook bodies, audit log diffs).
4. **Explicit audit tables, not soft deletes.** Domain actions that matter (contract extension, token application, coin movement, pack opening) write to purpose-built audit tables. Primary tables don't carry `deleted_at`.
5. **Derived state is computed or cached with a trigger.** For example, `card.current_tier` is a generated column derived from `career_fp_total`.
6. **Seasonal records always carry `season_id`.** Lets us archive / purge by season without expensive joins.
7. **Canonical MLB IDs are preserved.** `team.bdl_team_id`, `player.bdl_player_id`, `game.bdl_game_id`. Our UUID primary keys are stable across provider changes.

---

## 2. Naming & Convention

- **Table names:** singular snake_case. `card`, `contest_entry`, `webhook_delivery`.
- **Column names:** snake_case. `user_id`, `career_fp_total`.
- **Primary keys:** `id` (uuid, `gen_random_uuid()`).
- **Foreign keys:** `<table>_id`. `user_id` is the only exception — always references `auth.users.id`.
- **Timestamps:** `created_at`, `updated_at` on every mutable table. Default `now()` on create. A Drizzle trigger maintains `updated_at`.
- **Enum types:** `pg_enum` via Drizzle's `pgEnum`. Enum names are singular: `card_tier`, `game_status`.
- **Booleans:** positive framing. `is_active`, `is_postseason`. Never `is_not_x`.

## 14. Row-Level Security (RLS) Policy Summary

Every table has `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;` set. Policy families:

### 14.1 `owner_only`
User can SELECT/INSERT/UPDATE/DELETE where `user_id = auth.uid()`.

Applied to: `card` (non-vaulted), `token`, `token_application`, `coin_transaction` (read only), `contest_entry` (read own; write via service), `pack_opening` (read only), `contract_extension` (read only), `team_milestone_state` (read only), `team_milestone_award` (read only), `user_season_state` (read only; write via service functions).

### 14.2 `public_read_owner_write`
SELECT for anon + authenticated; INSERT/UPDATE/DELETE where `user_id = auth.uid()`.

Applied to: `profile`, `manager_account` (write via service), `vault_entry` (write via service), `card` where `is_vaulted = true`.

### 14.3 `public_read_service_write`
SELECT for all; writes only via service role.

Applied to: `season`, `team`, `player`, `game`, `game_event`, `contest`, `economy_config`.

### 14.4 `service_only`
No anon/authenticated access. All operations via service role.

Applied to: `webhook_delivery`, `webhook_failed`, `moderation_flag`.

### 14.5 `admin_only`
Access gated on a custom `app_metadata.role = 'admin'` claim on the Supabase Auth JWT.

Applied to: `manual_grant` (write), `moderation_flag` (write), `economy_config` (write).

### 14.6 Example RLS (`card`, owner-only for active rows)

```sql
ALTER TABLE card ENABLE ROW LEVEL SECURITY;

CREATE POLICY card_owner_read ON card FOR SELECT
  USING (
    (is_vaulted = true)                -- public vault read
    OR (user_id = auth.uid())          -- owner full visibility
  );

CREATE POLICY card_owner_write ON card FOR INSERT
  WITH CHECK (user_id = auth.uid());

CREATE POLICY card_owner_update ON card FOR UPDATE
  USING (user_id = auth.uid())
  WITH CHECK (user_id = auth.uid());

CREATE POLICY card_owner_delete ON card FOR DELETE
  USING (user_id = auth.uid());
```

## 15. Computed Fields & Triggers

### 15.1 `card.current_tier`

Generated from `career_fp_total` via trigger:

```sql
CREATE FUNCTION recompute_card_tier()
RETURNS TRIGGER AS $$
DECLARE
  thresholds jsonb;
BEGIN
  SELECT tier_fp_thresholds INTO thresholds FROM economy_config
    WHERE effective_from <= now()
    ORDER BY effective_from DESC LIMIT 1;
  NEW.current_tier := CASE
    WHEN NEW.career_fp_total >= (thresholds->>'diamond')::numeric THEN 'diamond'
    WHEN NEW.career_fp_total >= (thresholds->>'gold')::numeric    THEN 'gold'
    WHEN NEW.career_fp_total >= (thresholds->>'silver')::numeric  THEN 'silver'
    ELSE 'bronze'
  END;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER card_tier_on_fp_change
  BEFORE UPDATE OF career_fp_total ON card
  FOR EACH ROW EXECUTE FUNCTION recompute_card_tier();
```

### 15.2 `card.is_expired`

Auto-set when `contract_plays_remaining` drops to 0. Cleared when it rises again.

### 15.3 `updated_at` maintenance

A generic trigger on every mutable table:

```sql
CREATE FUNCTION touch_updated_at()
RETURNS TRIGGER AS $$
BEGIN NEW.updated_at = now(); RETURN NEW; END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER t_touch_updated_at BEFORE UPDATE ON <table>
  FOR EACH ROW EXECUTE FUNCTION touch_updated_at();
```

### 15.4 `user_season_state.coins` integrity

A `DEFERRED` constraint (or transactional SQL function `spend_coins / credit_coins`) updates `coins` and inserts a `coin_transaction` atomically. No direct `UPDATE coins` is allowed outside the function.

### 15.5 `manager_account.manager_level`

Recomputed from `manager_xp` on update via trigger; threshold curve lives in `economy_config.manager_xp_sources`.

### 15.6 `season_fp` denormalization

Trigger on `contest_entry` `final_score` update increments `user_season_state.season_fp` for the corresponding `(user_id, season_id)`.

### 15.7 `tokens_triggered_count` / `tokens_applied_count` on `card`

Trigger on `token_application` updates — increments `card.tokens_applied_count` on insert, and on update of `triggered`, increments `card.tokens_triggered_count`.

### 17.2 Initial migration set

Ordered to satisfy FK dependencies:

1. `0001_enums.sql` — pg enums
2. `0002_identity.sql` — `season`, `profile`, `manager_account`, `user_season_state`
3. `0003_mlb_reference.sql` — `team`, `player`, `game`, `game_event`
4. `0004_config.sql` — `economy_config` + seed row
5. `0005_cards.sql` — `card`, `contract_extension`, `vault_entry`
6. `0006_tokens.sql` — `token`, `token_application`
7. `0007_contests.sql` — `contest`, `contest_entry`, `contest_lineup_slot`
8. `0008_economy.sql` — `coin_transaction`, `pack_opening`
9. `0009_milestones.sql` — `team_milestone_state`, `team_milestone_award`
10. `0010_operational.sql` — `webhook_delivery`, `webhook_failed`, `manual_grant`, `moderation_flag`
11. `0011_functions.sql` — SQL functions (spend_coins, credit_coins, etc.)
12. `0012_triggers.sql` — updated_at, tier recompute, xp recompute, season_fp denorm
13. `0013_policies.sql` — all RLS policies
14. `0014_seed_economy_config.sql` — default config row
15. `0015_seed_season.sql` — first Draft Deck season

### 17.3 Migration guarantees

- **Reversible migrations** for launch. Each `.sql` file is paired with a `.down.sql` for rollback.
- **Destructive migrations** (DROP COLUMN, DROP TABLE) require a deprecation window: add `_legacy` columns, dual-write for a release, then drop in a later migration.
- **RLS enabled in the same migration** that creates a table. Never ship an RLS-off table to prod.

## 19. Data Retention & Deletion

### 19.1 On user account deletion

Supabase Auth user row deleted → `ON DELETE CASCADE` removes:

- `profile`, `manager_account`, `user_season_state`
- `card`, `contract_extension`, `vault_entry`
- `token`, `token_application`
- `contest_entry`, `contest_lineup_slot`
- `coin_transaction`, `pack_opening`
- `team_milestone_state`, `team_milestone_award`
- `manual_grant` (records tied to this user)

**Preserved (no cascade):**

- `game`, `game_event` (shared reference)
- `webhook_delivery`, `webhook_failed` (ops audit)
- `season`, `team`, `player`, `economy_config` (reference data)

### 19.2 Long-tail archival

- `game_event` rows older than 2 MLB seasons can be archived to cold storage (Supabase Storage) after year end. Not automated at launch; revisit when volume warrants.
- `webhook_delivery` rows older than 90 days can be pruned (ops-only data).
- `coin_transaction` is retained indefinitely for ledger integrity.

### 19.3 GDPR / CCPA

A `deleteUserAccount()` service function:

1. Anonymizes `vault_entry` records (strips `user_id`, keeps aggregate stats for leaderboards).
2. Triggers the CASCADE above.
3. Writes a `user_deletion` audit row (ops only).

Deferred: a user-initiated deletion flow in the profile drawer. For launch, support-handled.

**Table example (`card`):**

```typescript
// schema/cards.ts
import {
  pgTable, uuid, timestamp, integer, boolean, numeric,
} from 'drizzle-orm/pg-core';
import { cardTier } from './enums';
import { player } from './mlb_reference';
import { season } from './identity';

export const card = pgTable('card', {
  id: uuid('id').defaultRandom().primaryKey(),
  userId: uuid('user_id').notNull(), // FK to auth.users set in migration
  playerId: uuid('player_id').notNull().references(() => player.id),
  seasonId: uuid('season_id').notNull().references(() => season.id),
  acquiredAt: timestamp('acquired_at', { withTimezone: true }).notNull().defaultNow(),
  careerFpTotal: numeric('career_fp_total', { precision: 10, scale: 2 }).notNull().default('0'),
  currentTier: cardTier('current_tier').notNull().default('bronze'),
  contractPlaysRemaining: integer('contract_plays_remaining').notNull().default(15),
  extensionCount: integer('extension_count').notNull().default(0),
  isExpired: boolean('is_expired').notNull().default(false),
  appliedTokenId: uuid('applied_token_id'),
  isVaulted: boolean('is_vaulted').notNull().default(false),
  vaultedAt: timestamp('vaulted_at', { withTimezone: true }),
  tokensAppliedCount: integer('tokens_applied_count').notNull().default(0),
  tokensTriggeredCount: integer('tokens_triggered_count').notNull().default(0),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
});
```

Unique indexes, partial indexes, RLS policies, and triggers are added in raw SQL migration files alongside the Drizzle schema (Drizzle doesn't fully express them yet as of this writing).

## 22. Open Questions / Decisions to Lock Before First Migration

1. **UUID v7 vs v4.** Default to v4 for launch (`gen_random_uuid()`). Re-evaluate v7 once Postgres 18 becomes the Supabase default.
2. **`card` uniqueness partial index.** Confirm `(user_id, player_id) WHERE is_vaulted = false` is the right rule. Alternative: allow multiple active cards per player per user (would invalidate the dupe-auto-sell rule). Current doc assumes no-dupes.
3. **`economy_config` versioning.** The proposed design keeps older rows around for audit. Alternative: single mutable row + separate `economy_config_history`. Current doc is simpler.
4. **Partitioning `game_event`** by `season_id` at launch vs. later. Launching unpartitioned is fine; revisit in v2.
5. **`contest_lineup_slot` vs JSONB lineup on `contest_entry`.** Current doc goes normalized for query flexibility. Alternative: JSONB simplifies at the cost of harder queries. Normalized wins for launch.
6. **Denormalization of `season_fp`.** Trigger-maintained vs. computed-on-read view. Current doc denormalizes for leaderboard perf.
7. **`manager_account` rebuild-from-audit.** Should `manager_xp` be fully derivable from audit tables (coin_transaction, team_milestone_award, etc.)? Nice-to-have; at launch, the cached value is authoritative with audit tables as a fallback source of truth.
8. **Friend / follow tables.** Not in launch scope per the UI/UX spec. Schema ready to add a `user_follow(follower_id, followee_id)` table when needed.
9. **Notification persistence.** Do we write every notification to a `notification` table (so unread ones persist across sessions)? Deferred — sonner toasts don't persist today. Add if/when push notifications ship.
10. **Multi-tenant / org support.** Not in scope. All tables single-user-scoped.

## 24. Glossary

- **RLS (Row-Level Security):** Postgres feature that filters rows by SQL predicates tied to the request's JWT. Central to Supabase's security model.
- **Drizzle ORM:** TypeScript-first query builder / ORM that compiles to parameterized SQL. Schema defined in TS.
- **pg_enum:** Postgres enumerated type. First-class SQL enum; faster than a lookup table for small fixed sets.
- **Audit table:** Append-only log of a domain action (e.g., `coin_transaction`, `contract_extension`). Complements the current-state primary table.
- **Service role:** Supabase's privileged role (bypasses RLS). Used only by server-side cron + admin code. Never exposed to the browser.
- **Generated column:** A Postgres column whose value is computed from other columns; can be maintained via trigger in our setup (Postgres also supports `GENERATED ALWAYS AS ... STORED`, usable where the derivation is purely math).
